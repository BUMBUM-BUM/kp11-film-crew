# Субагент «Функционал» (Business Logic & Features)

Субагент отвечает за логику работы веб-платформы, права доступа, синхронизацию данных и серверные обработчики.

## Архитектура и подсистемы
1. **Роли и права доступа (`public/js/app.js`)**:
   - `isMasterOrAdminUser(user)`: доступ к созданию смен, удалению, выставлению оценок, панели управления.
   - Студенты: просмотр смен, подтверждение/отклонение приглашений, просмотр выставленных оценок и своего рейтинга.
   - Гости: просмотр расписания смен без административных действий.
2. **Жизненный цикл съёмочной смены**:
   - Создание смены: дата, локация, координаты, описание, технические спецификации, распределение по цехам.
   - Статусы участия членов съёмочной группы: `PENDING` -> `ACCEPTED` / `DECLINED`.
   - Посещаемость: `PRESENT` / `ABSENT` (с автоматическим штрафом к рейтингу при прогуле).
   - Завершение смены: фиксация оценок (1–5) для каждого участника, сохранение в `shoots.json`, пересчёт рейтинга в `users.json`.
3. **Серверные эндпоинты**:
   - `GET /api/shoots`, `POST /api/shoots`, `DELETE /api/shoots/:id`
   - `POST /api/shoots/complete`
   - `POST /api/crew/attendance`, `POST /api/crew/response`
   - `POST /api/auth/login`, `POST /api/auth/register`
   - `GET /api/notifications`
   - `POST /api/telegram/dispatch`, `POST /api/telegram/test`

## Инструкция по работе
- При расширении функционала обеспечивать поддержку как в `server.js` (Express + Prisma), так и в легковесном `local_server.ps1` с `shoots_helper.js`.
- Сохранять согласованность типов данных (числовые рейтинги, строки идентификаторов).
